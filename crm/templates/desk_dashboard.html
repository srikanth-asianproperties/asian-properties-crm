{# desk_dashboard.html (v1, 2026-09-22) — Desk mode D2: admin-only "Desk Dashboard", modeled on Sell.do's "System Default" dashboard + this app's own "Leads to Booking Summary" page (dashboard_booking_summary. html — read that file first if this one needs changing; the filter bar, breakdown-table pattern and Quick Summary cards are deliberately the same conventions, just laid out as a desktop-first grid instead of a stacked mobile sub-tab page). READ-ONLY — nothing on this page writes to leads/activity_log/site_visits/follow_ups/anything; app.py's desk_dashboard() route only ever SELECTs. Reached via base.html's "Desk Dashboard" drawer link (admin-only, gated on desk_dashboard_roles) or directly at /desk/dashboard — app.py's desk_dashboard() route 403s anyone not in DESK_DASHBOARD_ROLES before this template ever renders, same admin_required() logic, "Work As" impersonation included. Layout: a CSS grid, main area (~72%) + right rail (~28%), collapsing to a single column at <=1024px (DESK_MIN_WIDTH_PX — the same breakpoint the sidebar itself uses, so the two collapse together) so this still works stacked on a phone. All new CSS is scoped under a single .desk-dash wrapper so it can't leak into any other page. Bars: ONE Jinja macro, bar_table(), used for every "label -> count" breakdown AND reused per-project for the two cross-tabs (Lead Stage Stats Today / Site Visits by Project x Status) — pure CSS width percentages, no Chart.js, no new CDN, no external request of any kind from this page. Colors cycle app.py's DESK_BAR_COLORS (bar_colors context var).
